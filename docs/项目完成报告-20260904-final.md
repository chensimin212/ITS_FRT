## 三、运行链路（`ITS_FRT_V1.0.mq5:127-152`）

```cpp
void OnTick() {
    1. 节流：!IsNewBar() && !IsNewPrice() → return
    2. _gContext.Refresh()          // 账户→品种→持仓→市场状态；任一失败则 PauseEntry 并跳过本 tick

}
```

## 五、保留的三条防守链路

### 5.1 熔断与风控（`Manager/TradingManager.mqh` + `Module/RiskController.mqh`）

- 熔断判定：`AccountState.DrawdownPct >= CircuitBreakerDrawdownPct` → `TradingState.Terminate()` → 全撤单 + 全平仓；`E_TRADING_STATE` 单调推进 NORMAL → PAUSED → LIQUIDATING → TERMINATED，终止态不可回退
- 风控闸门 `CheckLot()`（RiskController.mqh:117 起）六道校验：手数合法性与 `MaxLotSize` → 单笔风险率 → 单向合计风险率 → 单笔保证金使用率 → 可用保证金容量（含 `MinMarginLevelPct` 折算）→ 品种单向总量限制
- 风险基准为固定净值 `FixedRiskEquity`，不随账户净值浮动（RiskController.mqh:82-84）
- ⚠ 说明：`CheckLot()` 只在开仓路径被调用，而开仓管理器已是空壳，故该闸门当前无实际调用方

### 5.2 定时清仓（`Manager/ClosingManager.mqh:73-96`）

```
pauseStart = DaySessionClose - (CloseBeforeMinutes + PauseBeforeMinutes)*60
liquidateStart = DaySessionClose - CloseBeforeMinutes*60

[pauseStart, liquidateStart)      → PauseEntry：仅禁开仓，存量仓位照常管理
[liquidateStart, DaySessionClose) → Liquidating：DeleteOrderAll + ClosePositionAll，未尽下一 tick 续做
```

按默认值（10 / 30 分钟）：23:19:59 起暂停开仓，23:49:59 起清仓。终止态下的清仓由 `TradingManager` 负责，`ClosingManager` 直接让行（ClosingManager.mqh:74）。

### 5.3 尾随止损（`Manager/TrailingManager.mqh`）

- 前置门控：`AnchorATR() <= 0` 直接跳过（TrailingManager.mqh:96-100）
- 锚定 ATR 取自 `MarketState.TradeATR`（TrailingManager.mqh:259-260）
- 双层锁盈：先算方向整体按新止损退出的锁定净收益，>0 则推进该方向全部腿（篮子锁盈，TrailingManager.mqh:134-152）；未触发则回退逐笔锁盈
- 止损锚点：`LowestPriceOn/HighestPriceOn(TradeTimeframe, TrailingLookbackBars, 1)`，即从上一根已收 K 线起回看，受 `TrailingMaxStopLossATR` 上限约束，并按 `TRAILING_BUFFER_RATIO = 0.05` 留缓冲
- ❌ 当前失效：见问题 2

## 七、阻塞与遗留问题（回测/实盘前必须处理）

### 问题 1 ❌ 阻塞：`CheckInputs()` 校验的字段 `LoadFunction()` 不再赋值 → `OnInit()` 失败

`Config/BaseConfig.mqh` 仍声明 73 个重构后已无人赋值的字段（三周期 `Macro*/Middle*/Trade*` 摆动与指标参数 41 个、`Market*` 判定 3 个、`Volatility*` 12 个、`Score*/Resonance*` 5 个、`Trigger*/ForwardSpace*` 7 个、`Stop*` 4 个、`MaxSpreadPoints` 1 个），而 `CheckInputs()`（BaseConfig.mqh:221-371）仍在校验其中约 40 个。`CTestConfig::LoadFunction()` 只赋值 14 个功能参数 + `TradeTimeframe`，其余字段保持零值，至少 14 处 guard 会命中，**第一处**即：

```cpp
// BaseConfig.mqh:266-274
int macroSeconds  = PeriodSeconds(MacroTimeframe);   // 未赋值 → PERIOD_CURRENT
int middleSeconds = PeriodSeconds(MiddleTimeframe);  // 未赋值 → PERIOD_CURRENT
...
if (macroSeconds <= middleSeconds)                   // 两者相等 → 命中
    return _logger.AlertError4Boolean("宏观周期必须长于中观周期");
```

后续 `StopLookbackBars <= 0`（BaseConfig.mqh:351）等亦会命中。链路：`CheckInputs()` false → `CBaseConfig::Init()` false → `OnInit()` 打印"配置初始化失败！"并返回 `INIT_FAILED`。

> 判定依据为静态审查（代码路径 + MQL5 对象成员零初始化），未做实盘/测试器实跑验证。修复后应以策略测试器单次启动作为实证。

**修复方案（二选一）**
- **A（推荐，与重构目标一致）**：从 `BaseConfig.mqh` 删除那 73 个字段及 `CheckInputs()` 中对应校验段，只保留系统 4 项、风控 7 项、执行 1 项、尾随 4 项、清仓 2 项与 `TradeTimeframe` 的校验
- **B（最小改动）**：保留字段，在 `CTestConfig::LoadFunction()` 中为被校验字段补齐合法默认值——但会把已删除功能的参数重新引回配置层，与"最小防御框架"目标背离

### 问题 2 ❌ 功能失效：尾随止损永不触发

`MarketState::Refresh()` 每轮硬置 `TradeATR = 0.0`（MarketState.mqh:76），`IsTradeATRReady()` 恒返回 false（MarketState.mqh:84-86）；而 `TrailingManager::Process()` 在 `AnchorATR() <= 0` 时直接 return（TrailingManager.mqh:96-100）。因此报告中"保留尾随止损"仅指代码保留，**运行时该链路不会执行任何一次止损推进**。

**修复方案**：在 `MarketState` 中恢复交易周期 ATR 计算（`iATR(_config.Symbol, _config.TradeTimeframe, period)` + 句柄缓存 + 就绪判定），并把 ATR 周期作为参数回补到 `FuncInputs.mqh`；`IsTradeATRReady()` 应反映句柄与数据可用性。

### 问题 3 ⚠ 语义偏差：`DaySessionClose` 固定为 23:59:59

`MarketState::Refresh()`（MarketState.mqh:66-79）把收盘时刻写死为服务器当日 23:59:59，未读取品种真实交易时段（`SymbolInfoSessionTrade`），也未处理周末与非交易日。对交易时段不足全天的品种（股指、商品、部分外汇会话），定时清仓窗口会偏离实际收盘。

**修复方案**：按 `SymbolInfoSessionTrade()` 取当日最后一个交易时段的结束时刻；无时段数据时再退回当日 23:59:59，并记录一条 warn。

### 问题 4 ⚠ 工程卫生：`.mqproj` 陈旧 + 12 个孤立文件

- `.mqproj` 删除约 22 个失效条目
- 孤立文件二选一：确认不再使用则删除（`TimingTracker`、6 个 Indicator、`OpeningSignal`、`IEntrySignal`、`EntryDecision`、`PositionSizer`、`StopLossCalculator`）；若要保留为将来扩展点，则须先修好其引用（Indicator 需要新的数据载体替代已删除的 `Model/MarketAnalysis.mqh`；`OpeningSignal` 需按 `IEntrySignal` 的 `CheckBuySignal/CheckSellSignal` 重写）

### 问题 5 ⚠ 设计确认：Pro 模式不可用

`CProConfig::LoadFunction()` 返回 false（ProConfig.mqh:56-58），一旦 `Core/Consts.mqh` 打开 `#define USE_PRO_CONFIG`，`OnInit()` 必然失败；且 `ProInputs.mqh` 无人 include。若生产部署要用 Pro 分支，需先补齐其参数装载。

### 问题 6 ⚠ 残留：加仓/补仓账本字段仍在

`Model/DirectionSequence.mqh:14-15` 的 `RescueCount/AddCount`，以及 `PositionState::ApplySequence()` 中解析注释层级的 `ParseLayer(comment, "R"/"A")`（PositionState.mqh:225-228）仍保留。功能无害（无人消费），但属加仓/补仓时代的残留语义，建议随问题 4 一并清理。

## 九、当前定位与结论

**这套代码现在是什么**：一个已经拆掉全部进攻逻辑的防守骨架——熔断、风控闸门、定时清仓、尾随止损四个模块的代码完整保留，分层结构（Core / Config / State / Api / Module / Manager）保持清晰，开仓侧以空壳维持接口，未来接回策略时不需要重构架构。

**这套代码现在不是什么**：不是可部署的 EA。除问题 1 会直接阻断 `OnInit()` 外，即使配置修好，当前也存在两个功能性空洞——开仓管理器为空壳（EA 不会自行建仓，而 `PositionState` 只接纳 `Symbol + MagicNumber` 匹配的持仓，PositionState.mqh:96-97，因此正常情况下它没有仓位可管），尾随止损被 ATR 恒零阻断。
